# verify：提交前的全套检查

## 怎么跑

```bash
bash tools/verify.sh
```

在仓库任意位置都能跑，约半分钟。脚本按顺序做两件事：

1. `python3 tools/check-data.py`：数据结构、交叉引用、出题硬规矩、文案计数
2. `node tools/e2e.js`：jsdom 模拟完整答题流程、双厂商切换、备份导入，以及**宽屏和手机两套星图的压盖核算**（课程名互压、星座交叠、课程名压到别的星、出画面）

输出只留结论和失败项，e2e 的完整输出在 `tools/e2e-last.log`。退出码 0 = 全部通过。

## 怎么解读

- **全部通过**：可以告诉用户「检查通过」，并附上脚本最后几行输出作为证据。没有跑、或者没看到输出，不要说通过
- **check-data 报错**：按报错逐条修数据。修 `docs/data/` 下的 JSON 要守 CLAUDE.md「改 docs/data/ 下的 JSON 时」的规矩（有 hook 把关）
- **e2e 某项 ✗**：先看它属于哪一段（输出里会带段落标题），再去 `tools/e2e-last.log` 看上下文。判断是**代码真坏了**，还是**数据变了、断言写死了**（CLAUDE.md 记过：曾把课程数、某个「无题库」样本写死）。后者要改断言让它跟着数据走，不能删掉断言了事
- **「星座交叠」「课程名压到别的星」**：给某门课加了知识点、星座变大了。按 CLAUDE.md「星座大小由知识点数决定」一节调 `courses.json` 的 `layout.slots`，必要时调大 `viewBox` 高度，再跑一遍
- **「测试崩溃」**：常见于数据错误让页面某一步没渲染出来（比如答案下标越界，测试点不到正确项）。先看 check-data 有没有一起报错

## 不要做

- 不要为了通过而删断言、放宽阈值或跳过某段测试。想缩小范围排查时可以临时注释，排查完恢复
- 不要只跑其中一项就说「检查通过」
- e2e 测不了真机行为（iPhone 上的下载、选文件、添加到主屏幕）。改到这些地方时，提醒用户上线后用真机试一下
