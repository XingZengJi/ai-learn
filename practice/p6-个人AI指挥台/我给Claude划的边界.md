## 问题一：哪些文件夹永远不给？为什么？

### 永不给

| 目录 | 里面有什么 | 为什么这条不能松 |
|---|---|---|
| `~/.claude/` | 登录凭据、**全部项目的会话原文**（本周区间就有 53MB） | 会话原文里有各项目的密钥讨论、客户方案、未公开的定价。给了它，等于把所有项目的历史一次性交出去 |
| `~/.config/gh/` | GitHub OAuth 凭据（已登录 `XingZengJi`） | 有了它就能以你的身份改任何仓库、开 PR、读私有库 |
| 商业项目 A 的 `.env` / secrets | 第三方服务的密钥与接口凭据 | 这是要向客户收费的产品，凭据泄露直接是运营事故 |
| 服务器配置仓的实机凭据 | SSH 等服务器配置 | 拿到就是服务器控制权 |
| **整个 `~/workspace`** | 14 个项目 | 这正是 k0302 点名的反面教材。图省事把大目录丢给它，等于放弃了「它能看见什么」这个唯一的控制点 |

### 有条件给

- **`~/.claude/projects/*.jsonl`**——周报的 ⑤ 悬挂事项、⑥ 重复摩擦、⑦ 消耗量都靠它，不读就没有内部那半张表。
  **但不是把目录给 Cowork 浏览**，而是只经由 `scripts/weekly-report-collect.py` 读取，且脚本**只提取三样东西**：
  `promptSource=="typed"` 的提示词、`usage` 的 token 数、时间戳。助手回复、工具输出、文件内容一律不进素材。
  > 区别在于：**给目录 = 它能翻任何东西；给脚本 = 只能拿到脚本提取的那三个字段。**

- **`ai-learn`**——可读（周报要引 p6 规格），但**素材与简报不可写进去**：它是公开仓库且 `docs/` 走 GitHub Pages，写进去等于发布。

### 本周实测到的两条，说明「给了文件夹」不等于安全

1. **软链能翻出工作区。** `2.1.216`–`2.1.217` 连修三个同类问题：后台会话经软链逃出工作区、定时任务跟着 `.claude` 软链写到项目外、worktree 隔离的 subagent 用 `git -C` 绕回共享 checkout。
   → **推论：目录边界是「意图」不是「围墙」。** 不能因为选了小目录就把敏感数据放在它隔壁。

2. **限制工具名 ≠ 限制能力。** Skill 触发实测里，`--disallowedTools "Edit,Write"` 之后，会话直接用 `Bash` 里的 `python3` 堆文档写文件——最后是被**独立的 Bash 审批**拦下的，不是被工具限制拦下的。
   → **推论：只要 Bash 可用，文件写入能力就还在。** 真正的闸是权限审批和沙箱，不是工具清单。

## 问题二：哪些内容不能进 Project 知识库？

Project 知识库会**长期留存并参与每一次生成**，所以标准比「这次对话能不能说」严格。

**不能进：**

| 内容 | 具体指 |
|---|---|
| 真实客户数据 | 商业项目 A 的注册用户、付费记录等。**这类数据是真实存在的，不是假设** |
| 任何凭据 | 第三方服务密钥、服务器登录、GitHub token，包括开发期临时顶替用的真实值 |
| 未公开的商业决定 | 定价、分成、部署成本这类还没对外公布的决定 |
| 会话原文 | 只放提取后的统计与摘要，不放对话正文 |
| 顺丰在职期间的内部数据 | 与 ai-job 项目同一条红线，跨项目适用 |

**可以进：** 关注对象清单、周报格式规则、历史简报、公开信源的链接与摘要、自己的写作偏好。

判断口径一句话：**这条内容如果出现在一份发给外人的简报里，我会不会后悔？** 会，就不进知识库——因为知识库里的东西迟早会被引用进产出。

## 问题三：简报发给别人，要不要标注 AI 参与？标到什么程度？

**现状：不发。** 这份周报是单人自用，p6 明确不做团队协作。所以当前无需标注。

**若要发出去：必须标注，而且标注不是加一行免责声明。**

具体到什么程度——三样东西必须一起发，缺一件就不要发：

1. **说明分工**：「由 Claude Code 采集素材与起草，本人审阅后发出」。不写「AI 生成」这种含糊说法，要说清哪部分是机器做的
2. **附上「我为什么选这些条目」**（周报附一）。这是全篇最需要被审视的部分——**选择比措辞更能误导人**
3. **附上「未核实/存疑」清单**（周报附二）。本期就有 4 条，包括一条与官方 changelog 表面矛盾的社区说法

理由：周报的核心价值是**筛选判断**，而判断是 Claude 做的初稿。只标「AI 参与」而不公开判断依据，读者无法评估这份筛选可不可信——那种标注是免责，不是透明。

**另外**：素材文件（`素材/*.md`）保留可复核状态，任何一条结论都能追回原始出处。

## 问题四：出了错，谁负责？

**我负责。全部。** Claude 不是共同作者，是我用的工具——工具用错了是用的人的责任。

这句话要能落地，得说清「错在哪一环、我该查什么」：

| 出错环节 | 表现 | 我的责任是 | 可查的证据 |
|---|---|---|---|
| **素材** | 抓漏了、抓错了、源不可信 | 事前定信源与阈值，事后核链接 | `素材/*.md` 全部带来源链接；脚本可重跑复现 |
| **判断** | 选了不该选的、漏了该报的 | **逐条读「我为什么选这些条目」** | 周报附一，含「没选什么和为什么」 |
| **格式** | 版式飘、规则没执行 | 改 Skill，不是每次口头纠正 | `.claude/skills/周报格式/SKILL.md` |
| **边界** | 读了不该读的、写了不该写的 | 事前选目录，事后看改了哪些文件 | 本文问题一 |

**不能用来免责的三句话**（写在这里是为了以后不许自己这么说）：

- 「是 AI 写的」——我选的载体、我定的信源、我发的稿
- 「我以为它只能动那个文件夹」——见问题一的软链事故，边界是意图不是围墙
- 「未核实那条我没注意」——附二就是为了让我注意，不看是我的问题

**一条硬规矩**：**查不到出处的具体细节，一律不进正文。** 本期已按此处理 4 条。宁可周报少一条，不可带一条查不到出处的进正文——一旦这条防线破了，整份简报的可信度就没有客观依据了。
