## ③ 裸聊 vs 三要素 对照（k0101 / k0102）

> ✅ **已跑，2026-08-01。** 载体已换，原话里的「AI 行业动态」改为「Claude Code 动态」。
> **跑法改动（已与用户确认）**：不在 claude.ai 网页版跑，而在本机起一个**空目录**跑 `claude -p`，
> 无 `CLAUDE.md`、无 Skill、无素材、无脚本（已确认 `~/.claude/CLAUDE.md` 不存在，用户级 skills 中无周报相关项）。
> 理由：我们这套装置本来就跑在 Claude Code 侧，**对照组用同一个引擎、只拿掉配置，差距才干净地归因于「配置」**。
> 若在网页版跑，测出的差距里会混进「网页版 vs CLI」这个无关变量。

**A. 裸聊版**——不建 Project、不给背景，直接要一份本周简报。

**实际发出的原话**（就这一句，没加任何背景）：

> 帮我写一份本周的 Claude Code 动态简报。

**产出存档**（跑了两次）：

| 文件 | 条件 | 结果 |
|---|---|---|
| `裸聊对照组/裸聊产出-A-无联网.md` | 默认权限，联网被拒 | ⚠️ **不作对照**。抓不到任何外部信息后，它把**自己的运行环境自省**当成了「本周动态」写——全篇标【实测】的都是它对当前会话工具集的观察，零条真实新闻、零条来源链接 |
| `裸聊对照组/裸聊产出-B-可联网.md` | `--allowedTools "WebSearch,WebFetch"` | ✅ **正式对照组**。只放开联网，其余照旧不给 |

> A 那版本身也是个发现：**不配权限时，模型会用「我能观察到的」填充「我该报道的」**。
> 这不是编造——它每条都如实标了【实测】并写明缺口——但一份没有增量维度的「周报」等于没有周报。

**B. 三要素版**——模板已按临时清单填好，**改写后**再发（禁止原样复制，这是教练规则第 1 条）：

> 【场景】我是产品经理，非技术背景，每周给自己出一份 AI 行业动态简报。关注对象：Claude / Claude Code、OpenAI（ChatGPT 与 API）、MCP 生态、Agent 与 Skills 生态。我关心的是**这些变化会不会改变我自己的工作方式**，不是行业大盘。
> 【任务】按「本周发生了什么 → 谁受影响 → 我该注意什么」三段成稿，每段 200 字内。
> 【规则】每条结论必须带来源链接；查不到出处的具体数字直接标「未核实」，不要写进正文；不要用「赋能/抓手/闭环」这类词。

**改写时至少动一处**——比如把「我关心的是」那句换成你真正的判断标准。原样发出你就没练到 k0102。

**实际情况：三要素从未以「一句提示词」的形式发出过。** 它在 07-31 那次实跑里被**拆进了三层配置**：

| 三要素 | 落到哪 |
|---|---|
| 【场景】我是谁、盯什么 | `weekly-report/CLAUDE.md` + 关注对象清单 13 条 |
| 【任务】三段结构、篇幅 | Skill `周报格式` 的「结构」一节 |
| 【规则】带来源、未核实标注、禁用词 | Skill 的「写作规则」+ 三道闸 |

**所以对照组 B 的实体不是一段提示词，是 `本周/周报-2026-07-31.md` 这份成稿**——
它由一句「出这周的周报」触发（Skill 触发实测见 ⑥，三次全中）。

> 📌 **这本身就是 k0102 → k0104/k0108 的过渡点**：教案假设三要素写在一次对话里，
> 而一旦这件事每周都要做，三要素就不该留在提示词里，**该沉到配置层**。
> 「同一段多步骤指令打过两遍字，就是该做 Skill 的信号」——这条在本项目上是跳过打第二遍直接沉下去的。

**C. 差在哪**（这三条是阶段 2 建 Project 的证据）：

> 对照材料：`裸聊对照组/裸聊产出-B-可联网.md` ｜ `weekly-report/本周/周报-2026-07-31.md`
> **前提结论：裸聊版并不烂。** 它列了 12 条一手来源、7 条 MCP 破坏性变更、每节还写了「判断」。
> 单看「像不像一份专业周报」，它可能比配置版更像。差距不在质量，在下面三条。

**1. 它不知道读者是谁，于是默认读者是一个技术团队。**
裸聊版第 8 节「建议动作」8 条：团队统一升版本、自建 MCP server 排查 Sampling 依赖、关键流水线补
`fallbackModel`、按每任务成本重做模型选型……**单人、非技术、订阅制的我，一条都执行不了。**
配置版每条都锚在我手上正在做的事（写 CLAUDE.md、写第一个 Skill、两条悬挂承诺）。
→ **Project 要写**：单人自用、非技术背景、订阅制不按量计费、无团队无 CI 无自建服务；
凡是需要团队或工程基建才能落地的建议，不写。

**2. 差的不是「抓得全」，是排序依据。**
两边互有遗漏：裸聊版抓到了 07/29–30 两次故障和 CLI 发版停摆（配置版漏了），
却漏了 HN 462 分那篇官方上下文工程博客（配置版的头条）。**所以这不是覆盖度问题。**
真正的差别是排什么在前：裸聊版按**事件本身的量级**排（MCP 规范改版当头条），
配置版按**「会不会改变我下周的做法」**排（一篇讲怎么写 CLAUDE.md 的博客当头条，因为我正在写 CLAUDE.md）。
→ **Project 要写**：排序标准是「这条会不会改变我自己的做法」，不是事件重要性；
对我无动作项的大新闻，压成一句备查，不展开。

**补充（08-01，网页版裸聊跑完后加）**：还有一条差异，是三条之外的意外发现——

> **裸聊不稳定。** 同一句话、同样没配置，网页版和本机 `claude -p` 两次产出**只有一小部分重合**。
> 无法区分这是平台差异还是采样随机（要区分得多跑几轮，不值得）。但结论一样：
> **裸聊每次给你什么，你控制不了。** 配置版的稳定性不来自模型，来自 Skill 把结构钉死了。
> 这条是 FR-11「格式固化」的直接证据——原来只当它是省事，其实它买的是**可复现**。

另外印证了 ③C 第 1 条：**网页版裸聊也没问「你是谁」**，直接上网查了就写。
它不会向你要背景，**它会替你假设一个**——而你不会知道它假设了什么。

**3. 它给了来源，但给不了「可审性」。**
裸聊版列了 12 条来源，却没有「我为什么选这些条目」，也没有「哪几条没核实」——
我拿到它只能**整份信或整份不信**，没法抽查它的判断。
配置版附一写明了候选 60+8+25 条筛成 3+2+1 条的理由（含「没选什么和为什么」），附二列了 4 条存疑。
→ **Project 要写**：文末必带选择依据 + 未核实清单。
**这条是三条里最本质的**——前两条是「写得对不对」，这条决定「我有没有能力发现它写错了」。

> 判断标准：一条纠正如果下周还会再说一遍，它就该进指令；只是这次特殊情况，就不进。

**⚠️ 第 6 条和前 5 条不是一回事，值得单列。**

前 5 条都是**用户看着产出不满意，开口纠正**。第 6 条不是——用户没有不满意，
是 08-02 出稿时**方法自己暴露了缺陷**：07-31 的快照存的是摘要，做 diff 时分不清
「官方新增」和「上次没记」，那一期 ① 因此少了一整块，只能整批按未核实处理。
用户说的「可以」是**批准**，不是纠正。

> 这说明纠正点有两个来源：**用户开口** 和 **产出复盘**。
> 只盯前者，会漏掉所有「用户看不出来、但结果已经错了」的那类——
> 而这类恰恰是委托出去之后最危险的，因为审的人不知道该审什么。
> **对策**：每期成稿后自查一句「这次有没有哪一步是靠运气过的」，有就按纠正点记。

**⚠️ 提取完发现的事（这条影响阶段 2 怎么做）**：

6 条纠正里，**3–6 条全是周报专有的，而且已经沉进 Skill 了**；剩下的 1、2 两条**全是跨项目属性**——
「先给计划再动手」和「说人话」跟周报没关系，写代码、做求职材料时同样成立。

> **所以「Project 自定义指令」这一层，在本项目里几乎是空的。**

## ⑤ 三模式手感对比（k0103）

同一件事在三种模式里各开个头，**不用做完**，只需体会差异。

> 填写说明（2026-08-01）：**Cowork / Code 两格有实证可填，Chat 那格是真空的**——
> 本项目从立项到出稿全程在 Claude Code 侧，claude.ai 网页版一次没开过。
> 按非功能需求「做不了要如实标注」，不补写体感。**这格留到阶段 2 建 Project 时顺手补**，
> 那时你必然要开网页版，一次就能填掉。

| 模式 | 我试了什么 | 手感 / 什么时候该用它 |
|---|---|---|
| **Chat** | ✅ **已补，08-01**。claude.ai 网页版，不建 Project、不给背景，发同一句「帮我写一份本周的 Claude Code 动态简报。」 | **它没问我任何问题**，直接上网查了就写。产出与本机裸聊 B 只有**一小部分重合**。→ 手感：**它不会向你要背景，它会替你假设一个**。适合：我还不知道自己要什么、需要来回问的时候——但那得**我主动问**，它不会先问我 |
| **Cowork** | 出 07-31 那份周报：给一个文件夹、一句「出这周的周报」，它自己跑脚本、读素材、筛选、写文件 | **我不在场它也能推进。**代价是我得**事后审**——附一那张「为什么选这些」就是为了让事后审查成为可能。适合：交付物形状说得清、中间步骤我不想逐步盯 |
| **Code** | 同一个环境。写采集脚本、跑 Skill 触发实测（`claude -p` 起空会话）、diff 正副本 | 与 Cowork 的界线在**这个工作区里是模糊的**——同一个 CLI。真正的区别是我给了它什么范围：给 `weekly-report/` 是 Cowork 式委托，给 `scripts/` 写代码是 Code 式 |

**课程给的判断标准**：Chat 用来**想**，Cowork 用来**做**。判断一个任务该交给谁，看它平时是**你自己动手做的事**，还是**拿来问一问的事**。

**我的版本（FR-3，一句话规则）**：

> **我能不能一句话说清交付物长什么样？说得清就交出去（Cowork），说不清就先聊（Chat）。**

这条在本项目里**真的被执行过，且两边都用到了**：

- 「载体选新闻还是项目进度」「资讯种类要不要补」「③ 改成什么」——**都是聊出来的**，因为当时我说不清要什么
- 「出这周的周报」——**一句话交出去**，因为那时交付物形状已经被 Skill 固定住了

> 📌 顺带一条实测教训（07-31）：在第一类问题（还在聊）上，Claude 直接开工把活干了。
> **说不清交付物却让它动手，产出必然要返工。** 这条规则不只是分工，也是防返工。

## ⑥ Skill 触发实测（k0304）

> 内容属阶段 3，因尚无阶段 3 工作表，暂记于此。实测日期 2026-07-31。
> Skill 位置：`weekly-report/.claude/skills/周报格式/SKILL.md`
> 方法：`claude -p "<提示词>" --output-format stream-json` 起全新会话，看 Skill 是不是被自动调用。

| # | 描述写法 | 提示词 | 结果 |
|---|---|---|---|
| 1 | 完整（含触发词 + 使用场景） | 「出这周的周报」 | ✅ **第 1 个**工具调用就是 Skill |
| 2 | 完整 | 「汇总一下最近七天 Claude Code 有什么变化，还有我自己做了些什么」<br>**一个触发词都不含** | ✅ 仍是第 1 个调用 |
| 3 | 故意降级为 `周报的格式规范与写作标准。`<br>（只说自己是什么，不说什么时候用） | 「出这周的周报」（与 #1 同） | ⚠️ **仍触发，但降到第 2 步**——先跑了一次 `find` 翻目录才确认适用 |

**结论一（正面）**：描述里对**内容**的说明比关键词列表更管用。测试 2 那句话不含「周报」「简报」「weekly」任何一个词，靠语义就匹配上了。

**结论二（这次真正学到的）**：

> 描述不写「什么时候用」，代价**不是完全失灵，而是它得先翻一遍目录才能确认这个 Skill 适用**。

它之所以还能兜住，是因为本工作区上下文极强：skill 名字里就有「周报」、`CLAUDE.md` 讲了周报格式、目录直接叫 `本周/` `历史简报/` `素材/`。**换一个上下文没这么明显的项目，同样的坏描述就会真的漏掉。**

**⚠️ 如实标注：FR-11 要求的「一次没触发 → 改描述 → 再触发」完整来回，没有真正发生。**
三次实测全部触发。要凑出「不触发」那一幕，需把 skill 名也改成不含「周报」的代号，已属人为构造，故未做。
按非功能需求「做不了要如实标注，不装作做了」处理。

**顺带验证的两件事**（都与 FR-14 边界相关）：

- `--allowedTools` 有效：测试 1 里 Edit 被拒（"requested permissions to write... but you haven't granted it"）
- `--disallowedTools "Edit,Write"` 挡不住 Bash：测试 3 试图用 `python3` 堆文档写文件绕过，被独立的 Bash 审批拦下（"This command requires approval"）。**说明限制工具名不等于限制能力**——这条该写进《我给 Claude 划的边界》

三次测试均未改动任何交付文件。
