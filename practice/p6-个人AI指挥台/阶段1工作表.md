## ① 三个适配特征验证（c03 L03）

判断这件事到底该不该交给 Cowork。**包括不满足的那条也要写清楚**——「都符合」这种答案说明没认真验。

| 特征 | 满足？ | 你的具体流程是怎样的 |
|---|---|---|
| **多步骤**<br>不是一问一答 | ☐ | |
| **文件为本**<br>有素材有产出，不是聊完就完 | ☐ | |
| **跨工具**<br>跨网页/文档/表格等 | ☐ | |

**参考（这是示例，别照抄，看的是颗粒度）**：
> **多步骤 ✅** — 我周一先扫 6 个公众号和 3 个产品的更新日志，把值得记的粘进一个临时文档；周三筛掉过时的，按「对我们产品有无影响」排序；周四写成稿，通常要改两遍措辞。
> **文件为本 ✅** — 素材是我粘贴的一堆片段（散在备忘录里），产出是一份 Markdown，历史稿都存在同一个文件夹。
> **跨工具 ⚠️ 部分** — 主要是网页 + 文档，没有表格。数据类的东西我目前是截图，不做量化。

**结论**：满足 ___ / 3 条 →  ☐ 继续做 p6　☐ 换一件事（教练协助重新挑）

**教练的临时判定（针对上面那份临时清单的任务，非你的真实流程）**

既然载体暂定为「跟踪 AI 厂商与生态动态、每周出简报」，这个任务本身可以先判一遍：

- **多步骤 ✅** — 扫官方发布页/更新日志 → 筛掉与你无关的（大量发布对 PM 没影响）→ 判断影响面 → 成稿。至少四步，且第三步需要判断而非检索。
- **文件为本 ✅** — 素材是收集的片段，产出是可归档的简报，历史稿要能被下一周引用。
- **跨工具 ⚠️ 部分** — 主要是网页 + 文档。若你不做数据表格，这条只算部分满足。

**判定：2.5 / 3，可以继续。** 「跨工具」偏弱不影响立项——它影响的是阶段 4 你能从 Chrome 集成里榨出多少价值。

> **但这不能替代你自己的那一栏。** 你真实的周报流程可能和上面差很远（比如你其实是从社群/群聊里捞信息，那「跨工具」反而更强）。真实流程决定阶段 3 的文件夹怎么建，有空补上。
