## 一、先说三个设计取舍

写之前必须先摊开三件事，否则你会觉得项目划分很随意。

**① 22 门课里有大量重复，硬按课划分项目会让你重复劳动三遍。**

- `c11`（Claude API，17 个知识点）、`c14`（Bedrock，14 个）、`c15`（Vertex，15 个）是**同一套课程的三个平台版本**，1–61 课几乎一一对应。
- `c06`（4D 框架基础）+ 7 个行业定制版（`c12`/`c16`/`c17`/`c19`/`c20`/`c21`/`c22`）共 55 个知识点，**方法论是同一套，差别只在场景和例子**。

所以：c14+c15 不各做一个项目，而是合并成一个**「差异学习」项目**（P7）；行业定制版不按行业切，而是按**「你自己用」和「你教别人用」**切成两个项目。

> **2026-07-27 修订**：原 P7 设计的是「同一份代码换两朵云」的迁移项目。学习者明确表示**暂不开 AWS / GCP 账号**，该框架不成立，P7 已重新设计——见第三节。结论是好消息：c14/c15 的 29 个知识点里，**真正绑死云平台的只有 2 个**（`k1401`、`k1501`），其余全是多轮对话、评估、提示工程、工具调用、RAG、缓存、MCP、智能体，在 Anthropic API 上一样能做。

**② 分级依据是「你对结果负多大责任」，不是技术难度。**

这条借的是小微企业版第 7 课那个判断标准（分档看后果，不看技术）。四个级别：

| 级别 | 名字 | 你在这一级做的事 | 对应天区 |
|---|---|---|---|
| **L1** | 会用 | 把 Claude 用对，且知道它什么时候会骗你 | 🟢 第一天区 |
| **L2** | 会做 | 把你的方法固化成别人也能跑的流程 | 🟢🔵 交界 |
| **L3** | 会造 | 从零写出别人能接进去用的东西 | 🔵 第二天区 |
| **L4** | 会带 | 迁移平台、给真实用户交付、教会别人 | ⚪ 第三天区 |

**③ 有 11 个知识点受账号/订阅限制，做不了「真」的。** 不糊弄过去，第六节单列了清单和替代动作。

### P1 · 个人 AI 指挥台

> **级别 L1 · 会用｜难度 ★☆☆☆☆｜1–2 周｜前置：无**

**一句话**：挑一件你每周都得干的真事（比如竞品动态周报），把它从「每次打开对话框重新说一遍」变成「一个已经配置好、会自己跑的工位」。

**为什么是这个项目**：c01 和 c03 的知识点全是**功能**（Projects、Artifacts、Research、Cowork 任务、定时任务）。功能类知识点最怕的就是「点开看一眼就以为会了」。用一件真实的周期性工作串起来，每个功能都必须真派上用场，否则你会发现自己根本用不上它——那也是收获。

**交付物**（5 件）：
1. 一个 Claude **Project 空间**，里面放着这件事的背景资料与自定义指令
2. 一份用 **Research 模式**做的深度调研，附来源核对记录
3. 一份 **Artifact**（周报模板 / 小工具页），能分享出去
4. 一个 **Cowork 任务文件夹** + 一条**定时任务**，每周自动出稿
5. 一份**《我给 Claude 划的边界》**：哪些文件夹给它、哪些不给、为什么

### P2 · 4D 自诊手册 + 机器体检报告

> **级别 L1 · 会用｜难度 ★★☆☆☆｜1 周｜前置：P1（需要有真实协作经历可复盘）**

**一句话**：把 `c06` 的「人该怎么做」和 `c13` 的「机器是怎么回事」两面合起来，产出一份**只对你自己的岗位有效**的诊断手册。

**为什么是这个项目**：这两门课是整个体系里唯一**不产出软件**的部分，最容易被当成读物划过去。破解办法是强制产出物 —— 4D 的每一个 D 都必须绑定你自己的一次真实失败或真实收益，写不出来就说明没学到。c13 讲的四个属性（下一词预测 / 知识 / 工作记忆 / 可引导性）恰好一一对应 4D 的四个维度，是天然的一体两面。

**交付物**（4 件）：
1. **《我的 4D 使用手册》一页纸**——四个 D 各写：我在什么场景下用、我踩过的坑、我的检查动作
2. **《机器四属性对照表》**——四个属性各写：它的能力区 / 局限区 / 我的一次实例
3. 一份**勤勉声明**（Diligence 的正式产出物），说明你在什么工作里怎么披露 AI 使用
4. 一次**描述–甄别循环实录**：同一个任务迭代 3 轮以上，每轮记下你改了什么、为什么

### P4 · 让仓库自己看着自己

> **级别 L2 · 会做｜难度 ★★★★☆｜2 周｜前置：P3**

**一句话**：对象就是 `ai-learn` 这个仓库本身——把「每次改完题库要跑校验、要核对布局、要写中文提交信息」这些你现在靠记性的规矩，变成**跳不过去的机制**。

**为什么是这个项目**：`c07`（Claude Code 实战）讲的是「怎么把 Claude Code 从盯着用变成放心不盯着用」，这只有在一个**你真的在乎它别出错**的仓库上才学得会。而这个仓库刚好已经积累了一堆血泪规矩（JSON 排版不能整体 dump、加知识点会撑爆星图布局、出题的三条硬规矩）——它们现在写在 `CLAUDE.md` 里，而 `CLAUDE.md` 是**指导性建议，不是强制**。把该硬的部分下沉到 hook，正是这门课的核心命题。

**交付物**（6 件）：
1. 重写一版 **CLAUDE.md**，按「具体可核查 / 点名替代方案 / 当成要省着花的预算」的标准精简
2. 一个**验证类 Skill**：一条命令跑完 `check-data.py` + `e2e.js` + 星图间距核算
3. 一组 **Hooks**：PreToolUse 拦截「对 quiz.json 整体 json.dump」；Stop hook 强制跑校验
4. 一条 **headless / routine**：定时重跑数据校验并报告
5. 一个 **GitHub Action**：PR 上自动跑校验 + Code Review（**只标记问题，不批准也不拦下**）
6. 把 1–5 打包成一个 **Plugin**

|---|---|
| k0701 长会话的操控技巧 | 用一次大批量补题会话实练 Plan Mode / `/compact <说明>` / Rewind |
| k0702 一份真正被遵守的 CLAUDE.md | 交付物 1 |
| k0703 验证类 Skill | 交付物 2 |
| k0704 六档权限模式 | 六档各用一次，写下各自的适用场景 |

### P5 · 学习助教 MCP 服务器

> **级别 L3 · 会造｜难度 ★★★★☆｜2–3 周｜前置：P3**

**一句话**：写一个 MCP 服务器，把这个仓库的 `Course/` 笔记和题库变成 Claude 能直接调用的能力，再写一个命令行客户端把它跑起来。

**为什么是这个项目**：MCP 的三个原语（工具 / 资源 / 提示词）最难的不是写代码，是**判断该用哪一个**——课程给的捷径是「归谁控制」：工具归模型、资源归应用、提示词归用户。用这个仓库当素材，三者的分工天然清晰：抽题是动作（工具），读笔记是取数据（资源），「按这门课的笔记出题」是可复用模板（提示词）。

**交付物**：
- **服务器**：3 个工具（按知识点查题 / 随机抽一套测验 / 记录错题）、把 `Course/` 暴露为只读**资源**、1 个出题**提示词模板**
- **客户端**：命令行版，能 `list_tools` / `call_tool` / 读资源 / 用提示词
- **两种传输各跑通一次**：STDIO（本地）与 StreamableHTTP（远程）
- 一份《我的服务器 Inspector 调试记录》

**覆盖知识点（12）**

| 课 | 知识点 | 抓手 |
|---|---|---|
| c08 | k0801 MCP 架构 | 「MCP ≠ 工具使用」：区别在于**谁做了实现工作** |
| c08 | k0802 定义 Tools | 装饰器 + 类型提示自动生成 schema，不手写 |
| c08 | k0803 Server Inspector 调试 | 不接完整应用就能测，缩短反馈循环 |
| c08 | k0804 实现客户端 | 多数真实项目只需实现客户端或服务器之一 |
| c08 | k0805 Resources 资源 | 只读无副作用 → 资源；会改状态 → 工具 |
| c08 | k0806 Prompts 提示模板 | 把「怎么把一件事说清楚」变成共享资产 |
| c08 | k0807 三原语的控制权归属 | 判断该用哪个原语最快的捷径 |
| c09 | k0901 Sampling 采样 | 服务器反过来请求客户端调模型——让服务器自己生成题目 |
| c09 | k0902 通知与进度上报 | 批量出题时向客户端回报进度 |
| c09 | k0903 Roots 文件权限 | 只允许访问 `Course/`，不给整个仓库 |
| c09 | k0904 JSON 消息与 STDIO 传输 | 本地进程模式 |
| c09 | k0905 StreamableHTTP 传输与状态 | 远程模式 + 状态管理 |

**验收标准**：这个服务器**接进你自己的 Claude Code 并真的用它复习过一次**，不是跑通就删。

### P6 · 出题官：把笔记变成题库的 AI 产品

> **级别 L3 · 会造｜难度 ★★★★★｜3–4 周｜前置：P5**
> 这是**毕业项目**。

**一句话**：把这次「12 个 agent 并行补 682 道题、事后才发现全体踩坑」的经历，做成一个真正的产品——输入课程笔记，输出符合三条硬规矩的题库。

**为什么是这个项目**：它是唯一能自然吃下 `c11` 全部 17 个知识点的选题，因为每一块都对应一个真实需求，不是为了练而练：

- 笔记太长塞不进上下文 → **RAG + 分块 + 嵌入**（k1108）
- 语义检索找不准专有名词（比如「StreamableHTTP」）→ **BM25 + RRF 混合检索**（k1112）
- 题目必须是能程序解析的 JSON → **结构化输出**（k1104）
- **「出题的三条硬规矩」正好可以写成自动评分器** → **Evals**（k1105）：正确项长度比 > 1.6 就判不合格、题干含「选项二」就判不合格
- 简单课用 Haiku、难课用 Sonnet → **路由工作流**（k1110）+ **模型选型**（k1002）
- 同一份笔记反复出题 → **提示词缓存**（k1113）

**交付物**：一个能跑的命令行产品 + 一份《评估报告》（评分器抓出了多少条不合格题）+ 一份《成本账》（`response.usage` 实测）。

## 八、三个我没采用的方案，以及原因

**① 按课程一门一个项目（22 个）** —— 会做出 22 个玩具，且 c11/c14/c15 要把同样的事做三遍。项目的价值在于**强度和真实性**，不在数量。

**② 按知识点类型分（概念类 / 工具类 / 工程类）** —— 分完之后每个项目都不是一件真事，是习题册。学习者是 PM，最需要的恰恰是「做完能拿出去用」。

**③ 一个大项目吃下全部 175 个** —— 试过在纸上排，结果是一个既要做网页、又要写 MCP、还要办工作坊的怪物，中途放弃的概率极高。分成 9 个、每个都有独立交付物，任何一个停下来都不算白做。
