### 第一个 hook 的记录（2026-11-01）

- **文件**：`.claude/settings.json`（登记 hook）+ `tools/hooks/guard-data-json.py`（判断逻辑，开头注释写了原理和手动测试方法）
- **放在哪一层**：项目级 `.claude/settings.json`，随仓库提交。这是项目规矩，谁在这个仓库里用 Claude Code 都该被拦，所以不放个人的 `~/.claude/settings.json`，也不放不入库的 `settings.local.json`
- **拦什么**：只管 Write（整文件覆盖）和 Bash（命令或它运行的 .py 里对数据文件用 `json.dump(`）。Edit 是规矩里允许的改法，不拦
- **退出码**：2 才拦下，并把原因交给 Claude；1 只算「hook 出错」，工具照样执行
- **一写好就生效**，第一分钟就误拦了两次：
  1. 初版把「命令文字」和「命令里提到的脚本内容」拼在一起判断，一条只读的 `grep` 被拦。已改成命令和每个脚本分开判断
  2. 用 Bash 往文档里写「这条规则拦 json.dump( 和 docs/data/」，文字本身就同时提到这两样。hook 分不清代码和文档，这个误拦**保留**：很少见，改用 Edit 就绕开了，不值得为它把规则写复杂
  - 教训：规则写完，要拿「该放行的」也测一遍，误拦和漏拦一样要算
- **已知漏网**：`f.write(json.dumps(data, indent=2))` 不含 `json.dump(`，拦不住。批量补题脚本本来就要用 `json.dumps` 生成新块，没法一刀切，留给 Stop hook 跑校验兜底

### 第二个 hook 的记录（2026-11-01）

- **文件**：`tools/hooks/check-on-stop.py`，登记在同一个 `.claude/settings.json` 的 `Stop` 下
- **事前 vs 事后**：第一个 hook 在动手**之前**看命令文字，快，但只认得出写法；这个在 Claude 准备结束回复**之后**看改完的文件，不管用什么写法改的都逃不掉。两个配合，就是「门禁 + 出门检查」
- **查什么**：`docs/data/` 有未提交改动时才跑，平时零开销。① `check-data.py`；② 排版比对：数「压在一行的短数组 / 短对象」，比上次提交少了一半以上，就判定为被整体重写（实测整体重写后 quiz.json 从 237 处降到 2 处，knowledge.json 从 175 处降到 0 处，差距极明显）
- **退出码 2 在 Stop 上的意思**：不是「拦下工具」，而是「不让 Claude 停」，原因交给它接着修
- **防死循环**：修完再停时输入里带 `stop_hook_active: true`。这时还没修好也放行，否则修不好就永远停不下。但退出码 0 时 stderr 谁也看不到，所以改用 `systemMessage` 把问题**直接显示给你**，不靠 Claude 自觉汇报
- **不跑 e2e**：一次要一两分钟、占 1G 内存，每轮都跑太重，交给推送后的 GitHub Actions
- **测法**：在临时目录克隆一份仓库副本，分别制造「没改动 / 改了别处 / 正常小改 / 整体重写 quiz / 整体重写 knowledge / 压成一行 / 答案下标越界 / 第二次停」8 种情形，全部符合预期。真实仓库一行没动
- **写建议时踩的小坑**：修复建议初稿写「用 git stash 恢复」，但 stash 会把工作区**所有**未提交改动一起收走，可能牵连用户别的修改。改成只取回出问题的那一个文件
- **验收的真实结果，以及一次记录失实**：验收后用户说「拦下了」，Claude 据此在本文件写了「被拦下并自行改回」，**没有核实**。做交付物 2 时 e2e 崩溃，才发现 `answer: 9` 还留在 quiz.json 里，没被改回。最可能的经过：验收指令是「改完就结束，不要跑任何检查」，Claude 被拦一次后照指令没修；第二次结束时触发防死循环，放行并向用户显示了警告。结论：
  - hook **拦下了**，防死循环和「直接告诉用户」也按设计工作了，**但拦下 ≠ 修好**。最后兜底的是人
  - 这正是 k0708「先看 diff，不看摘要」：「拦下了」是摘要，`git status` 才是 diff。验收完应该跑一次 `git status` 确认没有残留，Claude 写记录前也应该先核实
  - 残留已在 2026-11-01 由 Claude 恢复成 HEAD 的值（只差这一个数字）
