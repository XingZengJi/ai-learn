## Description 不只是"写提示词"

Description 是 AI 素养里"和 AI 系统有效沟通"的能力,**它比单纯写提示词的范围更大——重点是营造一个人和 AI 都能有效协作的环境**。它分三个层面:

- **Product Description(产出描述)** —— 清楚定义你希望 AI 创造出什么
- **Process Description(过程描述)** —— 引导 AI 该怎么处理你的请求
- **Performance Description(表现描述)** —— 定义你希望 AI 在协作过程中表现出怎样的行为

**AI 读不了你的心思**——最终结果的质量,很大程度上取决于你有多清楚地表达了自己的需求、偏好的处理方式、以及想要的互动风格。**AI 系统是互动的伙伴,不是数据库或自动售货机**;提前把话说清楚能省时间,也能带来更好的结果。

## 练习:烂提示词改造

让 Claude 挑战你,给你一些写得很差的提示词,然后运用 Description 的三个层面去改进——清楚的产出描述、过程引导、表现规格。改完之后和 Claude 聊聊改进前后的差异,请它反馈这样的改进对它给出更好回应有什么帮助。之后互换角色,轮到你给 Claude 出烂提示词让它修改,留意 Claude 倾向于补充什么信息、怎么组织这些信息。

## 反思

- Description 的三个层面(产出/过程/表现)里,你觉得自己现在的 AI 互动可能忽略了哪一个?
- 回想一次没达到预期的 AI 互动,更好的描述技巧本可以怎么改善结果?

## 对产品经理来说

**"Process Description 和最终目标一样重要"这一点常常被忽略**——很多人只描述"我要什么结果",却不说"希望你怎么想这个问题",结果拿到一个技术上符合要求、但过程完全不是你想要的产出。这个洞察对写需求文档(PRD)也一样适用:只写"要达成什么"而不写"按什么思路去做",团队交出来的东西经常"技术上对,但不是你要的那种对"。
