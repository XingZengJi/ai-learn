## 把 Description 和 Discernment 用到真实项目上

这一课要把 Description 和 Discernment 用到第 7 课规划的那个贯穿全课的项目上。

**第 1 步:回顾项目计划。** 拿出第 7 课的项目计划,快速回顾一下哪些任务该由人做、哪些该用 AI 能力、哪些该协作,可以根据这段时间学到的东西适当调整计划。

**第 2 步:准备好 Description 的思路。** 和 Claude 说明这个项目,动手之前先想清楚:每个任务需要什么样的产出(格式、风格、篇幅、细节程度)?希望 Claude 用什么方法或步骤来处理?希望 Claude 在协作过程中表现出怎样的行为(简洁还是详细、挑战性还是支持性)?

**第 3 步:用"描述-甄别循环"执行项目。** 针对每个任务:

- **描述**你需要什么(产出/过程/表现三个层面都讲清楚)
- **甄别**拿到的东西的质量(产出/过程/表现三个层面分别评估)
- **根据甄别结果精炼**——反馈哪里好哪里不好,调整描述,反复迭代直到满意
- **融入你自己的专业判断**——加入你独特的视角、创意或专业知识,做最终决定保留/修改/舍弃什么,并对最终产出负责

对项目里的每个任务重复这个循环,直到完成整个项目。

## 反思

- 哪些描述方式带来了最好的结果,你注意到什么规律?
- Description 和 Discernment 哪个花了你更多精力?为什么?
- 实际执行和第 7 课的最初计划相比有什么出入?你做了哪些调整?

## 对产品经理来说

这个"描述-甄别循环"本质上就是一个**快速迭代的反馈环**,和产品开发里"提需求→看原型→给反馈→再迭代"的循环是同一个结构。它提醒我们:**和 AI 协作不是一次性把话说清楚就完事,而是一个持续收敛的过程**——第一次描述往往不够精确,真正让产出变好的是"甄别之后反馈、反馈之后再描述"这个循环本身,而不是指望一次提示词就写对。
