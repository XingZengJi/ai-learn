## 课程结构

**这门课的主线就是 4D 框架本身**,先建立概念,再逐个能力展开,最后落到一个贯穿始终的真实项目上:

1. **打底**(01–05)—— AI 素养是什么、为什么重要、三种协作方式(Automation/Augmentation/Agency)、4D 总览,以及生成式 AI 的技术基础与能力局限
2. **Delegation**(06–07)—— 三个组成部分(问题意识/平台意识/任务委派),并当场选定一个贯穿全课的实践项目
3. **Description**(08–09)—— 三个层面(产出/过程/表现),加一节提示词技巧 Deep Dive
4. **Discernment**(10–11)—— 三个层面(产出/过程/表现),并把它和 Description 一起用「描述-甄别循环」套到贯穿项目上执行
5. **Diligence**(12)—— 三个组成部分(创建/透明/部署),产出一份项目专属的「勤勉声明」
6. **收尾**(13–14)—— 结语回顾整个框架,延伸练习提供自定进度的深化方式(含用游戏练 Description/Discernment)

## 几条值得单独记住的

**AI 素养 = 以有效、高效、合乎伦理、安全的方式与 AI 协作**(01)—— 这门课的重心是人机协作本身,不是 AI 技术科普。

**三种协作方式:Automation / Augmentation / Agency**(02)—— 自动化(AI 按指令做具体任务)、增强(人和 AI 做思考/执行的伙伴)、自主授权(配置 AI 的知识和行为模式,让它独立代表你工作)。层级越往后,配置成本越高,换来的自主性也越大。

**4D:Delegation、Description、Discernment、Diligence**(03)—— 四个互不重叠的诊断维度,前三个管有效性和效率,Diligence 单独管伦理和安全。

**Problem Awareness 要放在 Platform Awareness 之前**(06)—— 先想清楚要解决什么问题,再问 AI 能做什么,顺序反了容易"为了用 AI 而用 AI"。

**Process Description 和最终目标一样重要**(08)—— 只描述"要什么结果"不描述"希望怎么做到",容易拿到"技术上对但不是你要的"产出。

**提示词工程的"秘密武器":直接让 AI 帮你改提示词**(09)—— 六个基础技巧之外,这是最省事的一条。

**Discernment 是 Description 的另一面,两者是持续的反馈循环**(10–11)—— "描述-甄别循环"不是一次性把话说清楚就完事,而是靠这个循环持续收敛。

**不同场景对"AI 使用披露"的期待不一样**(12)—— 学术论文、商业提案、内部草稿的合理披露标准完全不同,不该套用统一政策。

**AI 很强大,但不是魔法解决方案——有用和安全的程度取决于我们怎么参与**(13)—— 全课最值得带走的一句话,把"AI 表现好不好"的责任拉回到使用者身上。
